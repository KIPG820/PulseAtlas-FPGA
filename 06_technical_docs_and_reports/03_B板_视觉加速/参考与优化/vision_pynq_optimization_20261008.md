# PYNQ-Z2 视觉推理优化记录（2026-10-08）

## 本轮改动

- `tools/vision_pl_pack.c`：im2col 对同一输出行、无越界的步长 1/2 数据块使用 NEON 一次搬运 8 个字节；跨行、补零和边界仍使用原标量实现。量化计算保持原除法，未采用实测更慢的倒数乘法。
- `tools/benchmark_yolo_fpga_board.py`：增加 `--direct-patch-buffer`，让 im2col 直接写入 PYNQ DMA 输入缓冲区，避免先写临时数组再复制。
- `tools/test_vision_pl_pack.py`：增加宽范围量化边界压力测试和步长 1/2 向量路径样例。

## 板端结果

使用相同的 12 帧缓存图像（640×480）、3 帧量化校准、1 帧预热、8 帧计时；模型输入为 256×192，57 个卷积层交给测试位流的共享卷积 IP。该帧集没有人体，因此结果用于计时和数值一致性，不代表人体关键点精度。

| 路径 | OpenCV 线程 | 平均耗时 | 速度 |
| --- | ---: | ---: | ---: |
| 原始 v10、临时 patch 数组 | 1 | 1.408 s/帧 | 0.710 FPS |
| NEON + DMA 直写 | 1，复测 1 | 1.382 / 1.391 s/帧 | 0.724 / 0.719 FPS |
| NEON + DMA 直写 | 2 | 1.379 s/帧 | 0.725 FPS |

直接写缓冲区让传输阶段从约 117 ms 降到约 94–96 ms；整帧提升约 1–2%，幅度有限。C helper 在板端编译成功，扩展后的量化、im2col、反量化测试通过；拷贝 patch 和 DMA 直写两种路径的逐层误差统计、相对 PS 的最终输出误差统计相同。每次基准测试结束都重新加载了 R10 原位流。

## 接入边界

上述 FPS 来自临时加载的共享卷积测试位流，不是 HDMI UI 的实时 FPS。当前 R10 UI 的 `ecg_frontend.hwh` 使用 `nn_accel_0`/`nn_dma_0` 做 ECG 推理，没有 `shared_conv_0`；视觉基准位流包含 `shared_conv_0`，但不包含现有 `nn_accel_0`/`nn_dma_0`。因此本轮优化尚未接入正在使用的 UI，也不能把该测试位流直接当作可同时运行 ECG 神经网络和视觉推理的正式位流。

当时的测试位流不能直接用于共存。下述 v12 试验随后保留了两套加速 IP；因此“必须先统一/复用加速器”已不再是硬件装入的前提。当前约 0.725 FPS 距 15 FPS 仍差约 20 倍；单靠搬运微优化达不到目标。

## v12 ECG + 视觉共存试验

从 R9 ECG 工程单独克隆的 `bld/vp35_coexist` 同时保留 `nn_accel_0`、`nn_dma_0` 与 `shared_conv_0`。视觉核走独立的 HP3 DDR 端口，控制地址为 `0x40020000`；原 ECG 通路、HDMI、按键没有被删除。完整布线后占用 44,266/53,200 Slice LUT（83.21%）、107/140 BRAM（76.43%）、176/220 DSP（80%）；WNS +0.151 ns、WHS +0.017 ns，DRC 无 error（有 warning）。工程脚本分别是 `integrate_ecg_vision_coexist_v12.tcl`、`route_ecg_vision_coexist_v12.tcl` 与 `write_ecg_vision_coexist_v12_bitstream.tcl`。

板端临时加载后，ECG 的 `fold9_0000` 与 `fold9_0333` 金标准输出在 PS/PL 完全一致；完整 HDMI 程序自检的四组金标准也全部通过。合并位流上用相同的无人体缓存帧测视觉，PS 0.603 FPS、PL 0.724 FPS，与独立测试位流的结果一致。每次测试结束均重新加载 R10 原位流。

隔离的视觉 worker 能以约 15 FPS 采集摄像头，并成功切换到 `FPGA + DMA`。接入完整 HDMI 页面后，实际测得摄像头约 9–11 FPS、预览约 7–10 FPS、视觉推理约 3.5–4.2 秒/帧；这些是短时试验值，不是稳定验收 FPS。页面频繁整页重绘会占用 CPU；v12 改为仅在推理结果或重要状态变化时重绘文字，摄像头帧仍逐帧更新。即使完全停止文字重绘，预览可约 13.4 FPS，但视觉神经网络仍远慢于 15 FPS 目标。

v12 的软件包为 `artifacts/PulseAtlas_R12_ECG_Vision_Coexist_Trial_20261008.zip`，板端试验目录为 `/home/xilinx/pulseatlas_r12_coexist_live`。这是共存验证版：已证明两套 IP 同片、ECG 输出正确、视觉计算通路可运行；尚未验证人体关键点精度，也未达到目标视觉推理帧率。三帧启动校准若拍到空场景，可能不代表真人场景，后续需用真实人体帧验证并改进校准策略。正式 R10 包保持独立，未被覆盖。

## 并发压力复测与瓶颈定位

一次无超时保护的并发试验后 SSH 中断、电脑网口断链，板端进程状态无法远程核查；人工重启后网络恢复。不能仅凭这次事件断定是 FPGA 位流故障。后续所有试验改用外部 `timeout`、Python 线程栈定时转储及五秒状态记录，测试脚本是 `tools/probe_r12_concurrency.py`。下表为内置信号 ECG 约 1000 帧/秒、USB 摄像头拍摄当时场景的短时复测；视觉 FPS 只计**完成**的推理，摄像头与 HDMI 预览另算。

| 场景 | 已完成视觉推理 | 推理耗时 | 视觉模型 FPS | 摄像头采集 | ECG |
| --- | ---: | ---: | ---: | ---: | --- |
| v12 双核 + HDMI 视觉页，65 s | 3 | 最近 7.15–7.68 s/帧 | 约 0.13 | 约 7–8 FPS | 帧号到 59959，无错误 |
| v13 视觉线程固定 CPU1 + HDMI，70 s | 3 | 最近 6.76–7.26 s/帧 | 约 0.14 | 约 6–8 FPS | 帧号到 65535，无错误 |
| v12 双核，不刷新 HDMI，60 s | 11 | 最近 3.05–3.25 s/帧 | 约 0.31 | 约 12–13 FPS | 帧号到 55208，无错误 |
| v14 减少一次 1280×720 整帧复制 + HDMI，60 s | 3 | 最近 6.70–7.52 s/帧 | 约 0.14 | 约 7–9 FPS | 帧号到 55331，无错误 |

这几轮正常退出，板子保持在线；v13 和 v14 是分离试验目录，未替代 v12 发布包。单核隔离和少一次整帧复制没有实质提高吞吐量。显示刷新与相机标注共同消耗了大量 ARM 算力；即使去掉 HDMI，视觉模型仍只有约 0.31 FPS。启动时三帧量化校准在双核并发场景耗时约 30–35 秒，不能把校准阶段算作推理吞吐。

先前独立 FPGA 基准的 57 层卷积启动至完成累计计时约 98 ms/帧，包含主机 MMIO 启动和轮询开销，并非纯硬件周期数，也不覆盖整个网络，不能直接据此认定整网硬件 FPS 上限。该次基准打包约 390 ms、传输约 123 ms、解包约 163 ms；这些分项来自同一次较早的基准，不能与其他运行的总耗时混算。下一阶段需要减少逐层 PS↔PL 往返，并加速整个模型的主要运算图；在改变模型映射后重新做 PS/PL 输出一致性与真人关键点验收。

为评估 5 FPS 目标，重新核对固定 256×192 ONNX 图：96 个卷积共 444,268,128 MAC/帧，当前选中的 57 层占 399,080,688 MAC，约 89.8%。因此大多数卷积计算已被卸载，但逐层转换、im2col、缓存维护、剩余 CPU 算子和显示竞争仍占主导。5 FPS 对应每帧 200 ms、仅卷积有效吞吐至少 2.22 GMAC/s；这只是必要条件，不是可达性证明。优先路线是用原始特征图输入的新卷积接口、FPGA 窗口生成、连续量化子图与可复用计算阵列替换当前共享卷积路径，先用真实网络子块验证时间、资源和精度，再决定整网迁移。

## 首个连续子图 v2 原型

本轮在隔离克隆工程 `bld/vp37_fused_pair_v2` 中实现了首两个卷积层的 Conv+SiLU+Conv 连续执行核。相对 v1，把静态输入窗口从覆盖全尺寸降到 32 个值，权重缓存也收敛到首层需要的容量。HLS C 仿真与 C/RTL 协同仿真均通过；离线金标准覆盖第一层输出、SiLU/重定量交接和第二层输出，逐字节一致。HLS 估算 BRAM18=12、DSP=61、LUT=21,265；整合到 ECG+HDMI 克隆后为 LUT=46,535、FF=50,126、约 102.5 个 BRAM36 等效块、DSP=86。完整布局布线零 setup/hold 违例，WNS +0.072 ns、WHS +0.021 ns，时序余量较小。候选试验位流和 HWH 已生成并打包为 `artifacts/PulseAtlas_FusedPairV2_PynqTest_20261008.zip`。

板端金标准校验随后在隔离目录完成：首两个卷积的 scratch、SiLU 和最终输出均与离线整数金标准逐字节一致（0 mismatches）。但该两层子图自身耗时 1,573.96 ms，只有约 0.635 次/秒；它不是整网 FPS，也没有达到实时目标。测试后重新加载了 `/home/xilinx/pulseatlas_r12_coexist_live/ecg_frontend.bit` 及对应 `.hwh`，并确认 ECG+HDMI 程序恢复运行。早先一次未完成的板测曾导致网络中断，不能将其原因归结为位流或核本身。

此子图尚未接入完整 96 层图，也没有端到端 FPS 或真人关键点验证；不得把它描述成已达到 5 FPS。它目前证明的是可综合、资源显著下降、离线整数语义一致且整合设计能通过时序布线。

## 提高并行度的 PE2 整机综合结果

PE_OC=2 的连续两层核通过 HLS C 仿真及 C/RTL 协同仿真，但在隔离的 ECG+HDMI 整机克隆 `bld/vp38_fused_pair_v2_pe2` 中，综合报告达到 53,184/53,200 LUT，并出现 WNS −0.210 ns、WHS −0.167 ns。由于 LUT 已接近器件上限且综合时序不满足，未继续布线、生成位流或上板。该实验支持停止通过堆叠更多并行 PE 提速；后续应在保持现有视觉核资源级别的前提下，重做整图 INT8 执行与张量接口。

## 全图 INT8 量化试验（桌面精度基线）

用户提出允许少量精度损失，以减少逐层浮点/整数转换。本轮用 ONNX Runtime 静态校准构造了一个全图 QOperator INT8 参考模型：96 个 Conv、14 个 Add、20 个 Concat、84 个 Mul、83 个 Sigmoid、2 个 MatMul 和 1 个 Softmax 都转换为量化算子；Split、Reshape、Transpose、MaxPool、Resize 保持整数张量上的布局/采样操作。输入端量化一次，三路模型输出在边界反量化。权重使用逐通道 INT8，激活使用 UINT8；模型从 11,557,445 字节降至 3,163,546 字节（约减少 72.6%）。

精度试验使用板端保存的 `person_validation_20261007.npz`：前 8 帧用于 MinMax 校准，后 4 帧留出验证。两条路径都在 4/4 帧检出人体；框 IoU 均值 0.982；17 个关键点的平均偏移为 5.76 像素，躯干四点平均偏移 5.34 像素、最大 8.87 像素（坐标均映射到 640×480 原图）。这是与 FP32 参考输出的一致性，不是真实标注精度；样本来自同一人和同一段录像，不能代表不同姿势、距离或光照。

这证明“整图以 8 位量化张量运行、只在输入/输出边界转换”在软件语义上可行，但当前留出集偏移高于此前所选卷积层量化的约 2.9 像素平均差，尚不应作为替换版本。另一组 2026-10-08 缓存画面中，FP32 基线也未检出人体，因此没有用于量化精度结论。桌面 QOperator 文件由 ONNX Runtime 验证，尚未部署到 PYNQ，也没有板端 FPS 测量。

可复现实验脚本为 `tools/probe_yolo_int8_quantization.py`，当前最佳参考模型和逐帧报告分别在 `tmp/yolo11n_pose_full_qoperator_int8_probe.onnx`、`tmp/yolo11n_pose_full_qoperator_int8_probe.json`。同样 8/4 切分下，Entropy 与 MinMax 指标一致；99.999 百分位校准和有符号对称激活量化更差。仅把最后 9 个输出头卷积留在 FP32，躯干点平均偏移升至 6.64 像素；把注意力 MatMul/Softmax 留在 FP32，偏移约 5.55 像素。因此目前保留整图 UINT8 激活 + INT8 权重的 MinMax 版作软件基线，不据此推断有符号量化或混合精度会更准确。

接口侧的图结构计算显示，57 个当前 PL 卷积每帧的 im2col patch 约 6.23 MB，输入 INT8 特征图合计约 1.92 MB，patch 展开约为原特征图的 3.25 倍；这还未计 PS 端 FP32 输出张量处理。因而下一阶段优先评估静态激活尺度和量化误差，再实现以连续 INT8 特征图为边界的执行器：PL 内部生成卷积窗口/patch，卷积结果直接按输出尺度重定量为 UINT8，PS 的 Add、Concat、Resize、SiLU 等也消费和产出整数张量。AXI 端再按突发长度和端口分流做测量优化。不能仅凭模型文件变小就宣称 FPS 提升；仍需 PYNQ 上逐阶段测速，并用不同姿势真人画面核验关键点。

## PS/PL 全整数首版上板（2026-10-09 补记）

用户明确要求 PS 和 PL 都以整数特征图衔接。本次在独立 R12 克隆中实现 QOperator 图解释器：PS 的 SiLU、Add、Concat、MaxPool、Resize 和注意力 MatMul/Softmax 使用 UINT8/INT32 运算，96 个 INT8 权重卷积全部调用原有 `shared_conv_0`；仅摄像头输入边界与三路姿态解码输出边界转换。固定量化尺度使 83 处 SiLU 能以查表形式融合；另用查表执行 Concat 重标定。板端 96 个卷积输出及最终三路模型输出与 ONNX Runtime 的同帧整数金标准逐值相等（零差异）。代码见 `tools/vision_int8_graph.py`、`tools/vision_int8_pl.py`、`tools/vision_pl_pack.c`，HDMI 试验目录为 `tmp/pulseatlas_r12_int8_pl_live`。

隔离缓存帧连续测试在首帧权重准备后分别耗时 1.074、1.034、1.024 秒/帧；摄像头无 HDMI 短测模型约 1.48–1.53 秒/帧（约 0.57 FPS）；摄像头加 HDMI 视觉页短测约 3.44–3.66 秒/帧（约 0.23 FPS），相机约 10 FPS、预览约 7–8 FPS。它比 R12 的约 0.14 模型 FPS 有进步，但显著低于 5 FPS，不能把预览 FPS 当作推理 FPS。PS 图独立计时从早期逐元素计算约 2.7 秒降到查表后的约 0.45 秒；剩余 96 次调用的搬运、缓存维护，以及与 HDMI/相机的 CPU 竞争需要继续解决。该同帧逐值一致性不等于不同人体姿势的真实标注精度。

ECG 并发试验在视觉推理开始前因 ADS1298 初始化失败：原位流下设备 ID 为 `0xFF`，状态报告配置错误；板子重启后问题仍出现。PYNQ 默认 DMA `stop()` 会无限轮询，掩盖了原始错误；独立试验版已用有界停止和 DMA 复位处理，失败能报错退出。此硬件状态下不能声称 ECG+视觉已通过并发验收。原 R12 包没有被覆盖，板端独立目录为 `/home/xilinx/pulseatlas_r12_int8_pl_live`。

## 全整数逐层接口优化（2026-10-09）

在独立 INT8 试验版上缩小每层 PYNQBuffer 的缓存同步范围，静态量化偏置/倍率/移位/描述符只写入并同步一次，并将 PS 的 SiLU、Add、Concat 重标定改为 UINT8 原生 C 查表。96 个 PL 卷积和最终三路输出与 ONNX Runtime 同帧金标准逐值相等。隔离缓存帧连续两次为 0.753、0.747 秒/帧，较原来的约 1.03 秒/帧有改善；相机加 HDMI 的第 30 秒记录为 6 次完成、最近单次 2.69 秒、模型 0.28 FPS，相机 11 FPS、预览 7.6 FPS，较此前约 0.23 模型 FPS 有小幅改善。短测不能证明长期稳定性或真人定位精度。

整页剖析：PL 卷积 96 次调用共约 1.4–1.5 秒/帧，其中 PS 生成窗口约 0.64–0.69 秒、输出整理约 0.34–0.42 秒，PL 轮询阶段约 0.24–0.26 秒。PS 量化运算和 HDMI/相机并发仍明显消耗算力。当前共享 IP 必须由 PS 展开 im2col 并逐层收回输出，软件微调已不能将整个流程压到 200 毫秒。达到 5 FPS 需要重设计接受原始特征图的卷积窗口生成和连续子图执行，并在同片 ECG+HDMI 资源约束下重新布线、校验输出与真人关键点；现有 v2 连续双层核上板耗时约 1.57 秒，不能直接复用为提速方案。

另测视觉 worker 的 nice=0 和 CPU1 固定：nice=0 时模型短测可约 0.36 FPS，但预览跌到约 3–4 FPS；固定 CPU1 未兼顾两者。因此交付版维持原有 nice=10、非固定 CPU 调度，没有用牺牲 HDMI 预览换取这点模型速度。
